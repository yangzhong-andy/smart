# 员工入职与每月发工资分开管理

## 页面职责

- `/hr/employees`「员工入职与档案」：只办理人员入职、岗位/部门及离职资料维护。新增与编辑人员资料不会写入薪资字段、工资单或账户流水。
- 员工卡片「薪资设置」：分别维护试用期/转正的人民币底薪、岗位工资、满勤奖；个人社保、月休息天数和收款资料共用。未发生项目明确填 0；未填写不能当成默认金额。
- `/hr/payroll`「每月发工资」：选择工资所属月份，显式生成工资草稿，核实考勤/满勤奖/提成/奖扣/个税，再沿用现有审批与发放登记入口。

## 数据边界

1. 新入职员工的正式及试用期薪资金额在没有设置时写入 null（覆盖旧模型的默认值）；保留现有员工薪资不变。试用期字段与工资快照通过追加式迁移引入，不回补历史。
2. 人员资料与薪资设置使用各自的字段白名单提交，不以整份旧员工数据覆盖另一个区块；空字符串可明确清空原有联系方式等非必填信息。
3. 创建/更新/删除员工后清理员工列表缓存。新列表缓存增加版本段，以读取月休息天数。
4. 薪资设置仅影响之后新生成的工资草稿；不会重新计算或覆盖任何已生成、已审批、已付款工资单。
5. 工资生成跳过薪资未完整设置或当月休息天数不合理的员工，返回员工姓名及原因供页面展示；已存在的当月工资单仍按原逻辑跳过。
6. 生成时明确的零底薪、零满勤奖、零休息天数不再被旧默认值覆盖。入离职日期与月份边界统一按日历日期比较，避免服务器时区导致月初入职被误判为非整月。

## 试用期与实际转正（2026-10-15）

- 人员资料记录试用期开始日、预计转正日、实际转正日。新入职默认试用期，开始日未填则取入职日；无试用期人员可选在职。
- 预计日期仅记录展示，不自动改状态或工资。填写实际日期才确认转正；不得早于试用期开始或晚于离职日、当前上海日期。
- 转正月份以实际转正日分档：1—10号当月整月正式标准；11—20号当月试用期/正式标准各50%；21号至月末（含31号）当月试用期标准，次月正式标准。
- **11—20号统一半月加半月，不按实际日期或自然日比例拆分。** 例如试用期基础工资3000、正式4000，当月基础工资3500。基础工资、岗位工资、满勤奖标准分别加权到分；是否发满勤奖仍按考勤核实。
- 社保个人扣款保留原按月设置，不拆半；提成、奖扣及个税政策不变。
- 无实际转正日期的试用期人员只使用试用期标准，不用正式标准兜底。既有在职员工无试用记录时沿用原正式标准，不猜测历史转正日期。
- 转正月同时有入离职且适用各半规则时，提示人工核实折算口径，本次不自动生成；不擅自定义半月与非整月在职如何叠加。其他入离职折算沿用现有逻辑。
- 新生成工资保存 `salarySnapshot`：实际日期、适用规则、两套原始标准、权重、有效标准及在职区间。工资页可展开查看。此快照不随员工资料修改；既有工资不重算。手动编辑工资金额后，该快照仍表示“生成时”标准，而非编辑后的来源。
- 入职/更新/删除统一使用现有活动用户鉴权，允许 SUPER_ADMIN、ADMIN、MANAGER，普通用户仍拒绝。提交异常响应会明确提示HTTP状态并要求刷新确认，避免盲目重复提交；不据此声称已解决所有网络空响应原因。

## 本次不调整

- 除上述转正工资档位外，不定义新的入离职折算、加班、提成或个税算法。工资草稿继续沿用现有出勤预填/折算方式，必须人工核实后审批。
- 不自动生成工资，不自动付款，不对接银行转账，不回补或修改生产历史数据。部署需单独授权，并走受管发布流程。
- 不把页面拆分视为完成付款原子性、并发防重或完整审批锁定治理；现有付款与审批实现需要独立完善与验证。

## 本地验证

`employee-profile.test.ts` 验证字段白名单、未配置与零金额的区别、非法输入与员工状态展示。

`hr-workflow-routes.test.ts` 在隔离的存储/鉴权/缓存适配器下执行真实接口源码，验证人员保存不写工资、薪资保存不改人员、生成时跳过未配置员工且不覆盖已有工资。

`hr-workflow-ui.test.ts` 渲染入职/薪资弹窗，验证两类表单字段分离。

`employee-confirmation.test.ts` 覆盖1—31号档位、次月/跨年/闰年边界、预计日期不自动转正、实际日期校验、两阶段标准完整性和快照不联动。路由测试覆盖半月金额及社保不拆半、超级管理员权限、保存不写工资流水、非整月人工审核提示。
