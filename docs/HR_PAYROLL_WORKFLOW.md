# 员工入职与每月发工资分开管理

## 页面职责

- `/hr/employees`「员工入职与档案」：只办理人员入职、岗位/部门及离职资料维护。新增与编辑人员资料不会写入薪资字段、工资单或账户流水。
- 员工卡片「薪资设置」：独立维护人民币底薪、岗位工资、满勤奖、个人社保、月休息天数和收款资料。未发生项目明确填 0；未填写不能当成默认金额。
- `/hr/payroll`「每月发工资」：选择工资所属月份，显式生成工资草稿，核实考勤/满勤奖/提成/奖扣/个税，再沿用现有审批与发放登记入口。

## 数据边界

1. 新入职员工的六项薪资金额在没有设置时写入 null（覆盖旧模型的默认值）；保留现有员工薪资不变。使用现有可空字段，无数据库迁移或历史回补。
2. 人员资料与薪资设置使用各自的字段白名单提交，不以整份旧员工数据覆盖另一个区块；空字符串可明确清空原有联系方式等非必填信息。
3. 创建/更新/删除员工后清理员工列表缓存。新列表缓存增加版本段，以读取月休息天数。
4. 薪资设置仅影响之后新生成的工资草稿；不会重新计算或覆盖任何已生成、已审批、已付款工资单。
5. 工资生成跳过薪资未完整设置或当月休息天数不合理的员工，返回员工姓名及原因供页面展示；已存在的当月工资单仍按原逻辑跳过。
6. 生成时明确的零底薪、零满勤奖、零休息天数不再被旧默认值覆盖。入离职日期与月份边界统一按日历日期比较，避免服务器时区导致月初入职被误判为非整月。

## 本次不调整

- 不定义新的入离职折算、试用期、转正分段、加班、提成或个税算法。工资草稿继续沿用现有出勤预填/折算方式，必须人工核实后审批。
- 不自动生成工资，不自动付款，不对接银行转账，不回补或修改生产历史数据。部署需单独授权，并走受管发布流程。
- 不把页面拆分视为完成付款原子性、并发防重或完整审批锁定治理；现有付款与审批实现需要独立完善与验证。

## 本地验证

`employee-profile.test.ts` 验证字段白名单、未配置与零金额的区别、非法输入与员工状态展示。

`hr-workflow-routes.test.ts` 在隔离的存储/鉴权/缓存适配器下执行真实接口源码，验证人员保存不写工资、薪资保存不改人员、生成时跳过未配置员工且不覆盖已有工资。

`hr-workflow-ui.test.ts` 渲染入职/薪资弹窗，验证两类表单字段分离。
