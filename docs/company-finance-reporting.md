# 公司经营与财务分析中心

## 定位与边界

入口：左上角“系统切换” → 经营与财务分析（本系统），或财务中心 → 经营与财务分析（`/finance/reports`）。这是现有系统内的同一模块，沿用登录与部门菜单权限，不是新数据库、新独立服务或新的SSO账套。首期六张报表服务公司经营、资金和资产管理，不替代现有业务模块，也不是一套重新录入的独立账。

唯一业务事实源为当前 ERP 数据库。报表只读；不创建财务流水、不调整期初、不生成付款、不刷新 OAuth、不额外请求平台或汇率接口。复用订单利润引擎时，通过内部异步上下文切换为 system-only 模式，正常业务页面保持原行为。系统中缺少的官方费用、未关联业务和未设置汇率必须披露。

以跨境集团常用的“业务事实 → 财务口径 → 管理分析”分层为方向，不声称已具备完整集团总账、合并报表或审计能力。

## 首期六张报表

| 报表 | 当前事实来源 | 输出与限制 |
| --- | --- | --- |
| 公司经营总览 | 已保存的平台订单/成本、账户及流水 | GMV、暂估贡献、账面资金、平台覆盖与质量；不把 GMV 叫作会计确认收入 |
| 公司利润表 | 现有三平台利润引擎、已审批工资、指定公共费用申请 | 管理利润桥和成本组件；全量公司净利润保留待核实，不能从不完整成本推算净利润 |
| 店铺经营表 | TikTok/Shopee/Mercado Livre 已有订单与成本 | 店铺、国家、原币 GMV、参考人民币、贡献和状态；不随意分摊公司公共费用 |
| 资金收支表 | 已确认 CashFlow，按业务日期 | 原币实收实付、分类用途、内部划拨排除清单；非完整法定现金流量表 |
| 资产负债管理表 | 账户、库存资产引擎、已放款其他应收、审批待付 | 当前快照、阶段估值及已识别承诺；不混加平台结算/账户资金，不输出虚构的净资产 |
| 未来资金计划 | 当前资金和未结审批单据的已有到期日 | 原币 30/60/90 天情景、逾期项、未排期项；不是银行/PAGO可用现金承诺 |

Kwai/Amazon 利润暂未覆盖，必须显式显示，不按零经营处理。Shopee 广告只使用能唯一关联店铺且同币种的系统 AdConsumption，保留完整性警告。Mercado Livre 不补取支付 API，因此未落库支付费用仍标记缺项。

## 统一口径（不可破坏）

1. 销售、结算、回款是不同事件。销售收入不能再加一次平台提现或账户回款。
2. 内部转账/换汇的本金不是经营收入或费用；手续费用仍是外部支出。识别依赖既有流水类型及分类，分类错误需要在业务源修正。
3. 采购付款不是全部当期成本。未售存货属于资产，已售商品使用原有利润引擎成本；头程运费不得在已售成本和公共费用中再次扣除。
4. 账户从各自期初资金加已确认、带符号流水计算，仅加自身余额一次；不再加父级展示汇总。币种不一致时余额/预测为未知。
5. 不同币种不直接相加。人民币为已保存参考汇率估值；同币种多个账户汇率冲突时禁止平均或默认 1。它不是历史汇率、月末收盘汇率或汇兑损益。
6. 工资按工资月份披露整月审批成本，付款按现金日期披露；预支扣回不应减少本月劳动成本。尚缺雇主社保/公积金；个人敏感信息不进入报表。
7. 月账单应收/应付方向按 billCategory，金额沿用现有出纳付款规则。已有付款流水但仍未结清的异常单据不重复计划。
8. 工厂汇总账单与拿货付款覆盖关系未完整统一前，只纳入已审批付款申请，明确披露剩余采购承诺缺口。PendingEntry、物流单与付款申请不是额外一笔应付。

   物流批量付款通过 LogisticsCost.expenseRequestId 关联请求，月账单通过 consumptionIds 关联相同费用。已被审批月账单覆盖的部分仅保留一份；批量申请金额、币种或付款状态无法对应时，相关币种预测显示待核实，不擅自猜测净额。
9. 资产和计划是当前快照；经营期间过滤不构成历史期末重建。工厂未提货是合同采购承诺，不能无条件认定自有库存。
10. 缺值与零值不同；读取失败、缺成本、未核实汇率不得默认为零利润、零资产或零现金缺口。

## 分层与后续建设

### 第一阶段：只读管理视图（当前交付）

- 一个受保护的版本化 API：`/api/finance/company-reports`；六张报表使用同一查询结果，避免不同页面各算一遍。
- 统一响应：经营期间、快照时间、数据范围、来源状态、参考汇率、数据缺口、指标与来源链接。
- 管理员/超级管理员及 FINANCE_CENTER 可读；新菜单进入现有部门权限配置，不绕过配置白名单。普通员工不能靠直调 API 获得公司财务数据。
- 用户手动生成，不后台轮询；并行重复请求合并，异期间并行请求返回 429。最多 93 天、每平台 20,000 笔订单，基础明细 10,000 行保护；不悄悄截断。
- 三个平台引擎及库存引擎顺序执行；最多缓存两个小于约 1MB 的紧凑结果，120秒有效；响应 private/no-store，不缓存完整订单载荷。
- 各表分页、CSV 导出当前报表，带范围/口径/质量提示。导出字符串防公式注入。

### 第二阶段：统一核算维度与对账闭环

先补齐来源身份和关联，不复制事实：业务主体 → 平台 → 店铺 → 国家 → 仓库；组织 → 部门 → 成本中心；业务单据唯一 ID → 结算交易 ID → 流水 ID。

需要新增的治理能力：

- 统一支出/收入会计映射，区分资产、成本、期间费用、融资、权益及内部往来。
- 已有汇率来源、业务日、适用类型（交易/月末/预算）与版本；不得无记录覆盖历史报表。
- 订单成本完整度、平台应收释放、提现在途、钱包可用/受限余额与银行对账。
- 未归属主体、未映射 SKU、缺采购成本、未分摊物流、未排付款日形成异常清单；从报表下钻原单修复。
- 全部物流费用按原有多笔组成与分摊规则入商品落地成本，避免货柜成本双计。

这阶段完成后才开放主体/成本中心的独立损益筛选；数据归属不齐时不能只过滤账户就称作主体利润。

### 第三阶段：月结、会计映射与完整三大报表

- 期间状态：开放 → 对账 → 预关账 → 审批 → 锁定；重开需权限与审计。
- 存储只读的报表快照及来源 ID、规则版本、汇率版本、生成/审批人；快照是审计产物，不是第二套业务账。
- 建立权责收入确认、跨期费用摊销、固定资产/折旧、预付、借款、应交税费/社保、应付与权益。
- 单主体借贷映射校验后生成完整利润表、资产负债表及现金流量表；差异需解释，不能用“校准流水”配平。
- 集团层再增加关联交易标识、内部往来核对、合并抵销和外币折算；仅汇总多个公司不是合并报表。

### 第四阶段：预算与经营决策

- 月度预算/实际/差异：平台、店铺、部门、仓库和成本中心。
- 现金预测由已有付款承诺扩展为回款概率、付款优先级、税费及补货计划，预测版本与事实分离。
- 库龄/周转/滞销/跌价、单店贡献、营销边际、仓配成本和资金占用。
- 异常预警只读建议；不自动过账、付款、校准余额或抵销真实单据。

## 验证与发布

在本地使用隔离测试验证权限、金额规则、内部转账、汇率缺失、重复单据、预测边界和只读上下文；执行完整 check 与生产构建。无需 schema 迁移。发布仍需明确授权；不能在实现报表时顺带部署其他改动或更改生产数据。
