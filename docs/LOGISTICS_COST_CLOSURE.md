# 物流费用完结

柜子或批次至少有一笔关联物流费用，且所有费用的 paymentStatus 均为“已付”，自动显示费用已完结，并从新建费用选项中隐藏。零费用、未付、审批中等不自动完结。运输状态不参与判断。

- 柜子汇总直接关联费用，以及历史仅通过批次关联的费用；同一费用只计一次，直接柜子关联优先。不修改历史账单、流水、库存和运输状态。
- 新建费用默认隐藏已完结柜子；批次自身完结或其所属柜子完结时均隐藏。
- 重新打开设置 costsReopened=true；柜子重新打开后，其下自动完结的批次可补录，但批次独立手工关闭标记不变。成功新增费用后，同一事务清除所选批次和相关柜子的补录开关，恢复按付款状态判断；取消或失败提交不消耗补录机会。
- 完结前已登记的费用仍可请款、付款和补传凭证。
- 历史全已付记录立即自动完结，无需回写付款数据。日期取关联费用最后付款日期（缺失时取更新时间）。手工提前关闭入口和重新打开仍可通过费用完结管理操作。
- 新增费用接口也检查状态，并锁定所选批次及柜子，拦截旧页面提交。选择失效时整体报错，不会丢弃批次后生成无关联费用。
- 选择柜子但不选批次时直接关联柜子；跨柜选批次时各自保留真实柜子关联。

部署前执行随版本提交的迁移 `20261009090000_add_logistics_cost_closure`，为 Container 和 OutboundBatch 增加可空的 costsClosedAt。迁移不更改已有记录的业务状态；旧版本代码兼容新增列。

修正版追加迁移 `20261009120000_auto_paid_cost_closure`，为两张表增加默认 false 的 costsReopened 补录开关。未修改任何历史物流费用或财务数据。

验收：标记柜子完结 → 新建下拉及未筛选批次均不显示它；重新打开 → 未单独完结的批次恢复；独立标记批次 → 仅该批次隐藏；历史费用仍可查看/处理。还应验证两人同时操作时，旧表单向完结对象提交返回 409。
